## 為什麼順序跟論文不同

第 2、3 節本身就是先定義再使用,所以維持論文的順序。Introduction 不是:它用 MMIC、DSIC、OCA-proof 來陳述主要結果,而這三個詞到第 3 節才定義。所以放到最後讀。

## 單元(依閱讀順序)

每個單元列出:位置、需要什麼、以及讀之前先自己回答的問題。

1. **區塊鏈上的交易** — 第 2.1 節([連結](https://arxiv.org/html/2106.01340v3#S2.SS1))
   需要:無。
   讀之前:一個區塊的空間有限。你認為是誰決定哪些交易能放進去?

2. **基本模型** — 第 2.2 節([連結](https://arxiv.org/html/2106.01340v3#S2.SS2))
   需要:單元 1。
   讀之前:每筆交易有 size、valuation、bid 三個量。哪一個是別人看不到的?這為什麼重要?

3. **Allocation rule(分配規則)** — Definition 2.1、2.2 與 Remark 2.3,第 2.3.1 節([連結](https://arxiv.org/html/2106.01340v3#S2.SS3.SSS1))
   需要:單元 2;mechanism design(第 0 章)。
   讀之前:協定可以規定哪些交易「應該」被納入。它能強制執行嗎?

4. **Payment rule 與 burning rule(付款規則與銷毀規則)** — Definition 2.4、2.5 與 Remark 2.7、2.8,第 2.3.2 節([連結](https://arxiv.org/html/2106.01340v3#S2.SS3.SSS2))
   需要:單元 3。
   讀之前:協定為什麼可能把一部分手續費銷毀,而不是全部給 miner?

5. **以 first-price auction 為例** — Example 2.6([連結](https://arxiv.org/html/2106.01340v3#S2.Thmtheorem6))
   需要:單元 3、4。
   讀之前:把 Bitcoin「出多少付多少」的規則拆成三條:誰被納入、誰付給 miner 多少、銷毀多少。

6. **Transaction fee mechanism 的定義** — Definition 2.9([連結](https://arxiv.org/html/2106.01340v3#S2.Thmtheorem9))
   需要:單元 3、4。
   讀之前:不需要預測;這裡只是替單元 3、4 的三條規則合起來取名。

7. **使用者與 DSIC** — Definition 3.1 及其後一段,第 3.1 節([連結](https://arxiv.org/html/2106.01340v3#S3.SS1))
   需要:單元 6;dominant strategy(第 0 章)。
   讀之前:在「出多少付多少」的拍賣裡,你應該照這筆交易對你的真實價值出價嗎?

8. **Myopic miner 與 MMIC** — Remark 3.2、Definition 3.3、3.4,第 3.2 節([連結](https://arxiv.org/html/2106.01340v3#S3.SS2))
   需要:單元 6(Remark 3.2 另需單元 5)。
   讀之前:除了挑選要納入哪些交易之外,miner 還能對一個區塊做什麼來多賺?

9. **Second-price 類型的拍賣不是 MMIC** — Example 3.5([連結](https://arxiv.org/html/2106.01340v3#S3.Thmtheorem5))
   需要:單元 8;second-price auction(第 0 章)。
   讀之前:三個位置,最高的三個出價是 10、8、3,每個人都付最低的得標價。找出一個讓 miner 賺超過 9 的做法。

10. **Off-chain agreement 與 OCA-proof** — Definition 3.6、3.7,第 3.3 節([連結](https://arxiv.org/html/2106.01340v3#S3.SS3))
    需要:單元 7、8;Pareto improvement(第 0 章)。
    讀之前:假設每筆手續費都有一部分被銷毀。miner 和使用者私下可以做什麼交易,讓雙方都更好?
